## One password per person

Anything you hand out on a link can be forwarded, shared, and taken twice. A survey, a giveaway, a beta invite, an event registration, a claim form. The link cannot tell a real first-timer from the same person on a second browser.

It bites hardest in market research and academic panels. Bots, duplicate respondents, professional survey-takers and survey farms clear a simple screener and land in your data, so you pay for completes that are not real and clean it up afterward. HumanCheck moves the check upstream, before your first question, so only a real, unique, present human ever reaches it.

One idea holds the whole thing up: **every password is tied to one unique human and works exactly once.**

## Why the gate holds

Each password is a claim ticket. We only hand one to a person who just proved, on camera, that they are **live** and **unique**. Your survey platform enforces the ticket with its own built-in gate: Alchemer's <a href="https://help.alchemer.com/help/login-password-action">Login/Password action</a>, or Qualtrics' Authenticator, set to individual one-time passwords that deactivate after use. Your platform's feature, your platform's wording.

So every cheap trick fails: a shared link carries a spent password, a guessed password does not exist, a bot never earns one, and the same face can never get a second one for the same thing, on any device.

One honest limit: the check proves a real, unique human, and says nothing about how carefully they answer. Keep your speeder and attention checks.

## What we never touch

No photo is shared with you or with the platform on the other end, only a yes or no. You receive a verdict and a password, never a face, a name, or personal information.

## Works on more than these four

Nothing about the mechanism is specific to one platform. The check and the single-use credential are always the same; only the platform's own lock changes shape to fit. So the gate works anywhere you can hand each respondent a link or password that works exactly once.

| Platform | The credential | The platform's own lock |
| --- | --- | --- |
| **Qualtrics** | A one-time code on the link | The Authenticator in Survey Flow, where each code authenticates exactly once |
| **Alchemer** | A one-time password | The Login/Password action, individual one-time passwords that deactivate after use |
| **Tally** | A one-time token on the link | A hosted gate opens the form only for a valid token, and a webhook removes anything that slips through |
| **Typeform, Jotform** | A one-time token on the link | The same hosted gate, no guide written yet |
| **Google Forms** | A one-time token in a field | A small script checks each submission and removes the ones without a valid token |
| **Your own survey stack** | A one-time token | Your code asks us whether a token is real and unused before it saves the response |

The strength of the lock varies a little by platform. Qualtrics and Alchemer enforce it server-side before a single question shows, which is why those two came first, but the hosted wrapper plus uniqueness protect every platform. We are actively building out more guides.
